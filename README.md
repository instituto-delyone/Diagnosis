Diagnosis Instituto Delyone de Medicina e Tecnologia 
> **O caso não é o conhecimento. O caso é uma amostra do espaço clínico > produzido pelo conhecimento.**
>  O Diagnosis é um projeto de simulação e estruturação do raciocínio clínico. Sua arquitetura parte da representação estruturada do conhecimento médico para construir um espaço de possibilidades clínicas e, a partir dele, gerar estados de pacientes e casos clínicos para simulação.
> O projeto não é concebido como um simples banco de casos pré-escritos.
> A unidade primária é o conhecimento clínico estruturado; o caso é uma realização possível desse conhecimento.

Uma unidade de conhecimento deve permitir que o sistema reconheça e relacione elementos como: ● síndromes e condições clínicas; ● etiologias; ● mecanismos fisiopatológicos; ● fatores de risco; ● manifestações clínicas; ● sinais e sintomas; ● exames e achados esperados; ● diagnósticos diferenciais; ● critérios diagnósticos; ● tratamentos; ● complicações; ● evolução e possíveis trajetórias clínicas; ● relações entre diferentes entidades; ● origem e proveniência das informações. A estrutura deve permitir que um mesmo conhecimento sustente múltiplas apresentações clínicas plausíveis. 🔬 Conhecimento antes do caso O Diagnosis segue uma regra fundamental: > **Não transformar diretamente um resumo em um caso.** Os resumos são fragmentos de conhecimento destinados a preservar e facilitar a recuperação de conteúdos. Eles não representam, isoladamente, todo o conhecimento necessário para uma síndrome. Quando um caso é solicitado, a arquitetura prevê: 1. identificar o domínio ou síndrome pertinente; 2. consultar o conhecimento estruturado; 3. consultar as referências correspondentes quando necessário; 4. utilizar o resumo como contexto complementar; 5. reconstruir ou selecionar possibilidades clínicas compatíveis; 6. definir um estado possível de paciente; 7. gerar a apresentação clínica e sua evolução. Assim, o caso é consequência do conhecimento — não sua fonte primária. 🎲 Geração de casos A geração de casos busca representar a variabilidade existente na prática clínica. O mesmo conhecimento pode originar diferentes pacientes conforme variem, por exemplo: ● idade; ● contexto clínico; ● fatores de risco; ● apresentação; ● gravidade; ● manifestações; ● resultados de exames; ● comorbidades; ● evolução; ● resposta às intervenções. O objetivo é permitir que o raciocínio clínico seja exercitado diante de situações novas, em vez de simplesmente reproduzir casos previamente armazenados. 🩺 Raciocínio clínico O caso não deve ser apenas uma narrativa. As informações apresentadas ao usuário devem poder participar de um processo de raciocínio: ACHADO ↓ HIPÓTESES ↓ INVESTIGAÇÃO ↓ RESULTADOS ↓ REVISÃO DAS POSSIBILIDADES ↓ DIAGNÓSTICO ↓ CONDUTA ↓ EVOLUÇÃO Isso permite que a simulação represente a natureza dinâmica da tomada de decisão clínica. 🧩 Modularidade A Knowledge Base é organizada em módulos clínicos independentes. Cada módulo representa um domínio/síndrome específico e pode ser desenvolvido, revisado e carregado separadamente. O princípio de organização é: > **Um conhecimento → um arquivo canônico.** Isso evita acumulação desnecessária de versões e mantém a base mais previsível para manutenção, carregamento e auditoria. 🗂 Módulos clínicos A base clínica está organizada em 35 módulos principais, abrangendo: 1. O sistema deve distinguir, quando aplicável: ● conteúdo proveniente do resumo original; ● informação proveniente de fonte externa; ● conhecimento previamente estruturado; ● conflitos entre fontes; ● incertezas; ● lacunas ainda não resolvidas. A finalidade é evitar que uma informação seja incorporada à base sem que sua origem possa ser identificada posteriormente. 🚫 O que o Diagnosis não pretende ser O projeto não deve ser reduzido a: ● um banco de casos estáticos; ● uma coleção de histórias clínicas prontas; ● uma transformação direta de PDF em casos; ● uma recuperação de casos antigos como principal mecanismo de geração; ● uma base em que conhecimento e caso sejam tratados como a mesma coisa. A arquitetura parte de uma direção específica: CONHECIMENTO → POSSIBILIDADES → PACIENTE → CASO e não: CASO → CONHECIMENTO 🧪 Princípios de validação Uma estrutura de conhecimento deve ser capaz de passar, entre outros, por testes conceituais como: Generalização O mesmo conhecimento consegue sustentar mais de um paciente? Variação É possível alterar apresentação, contexto ou gravidade sem perder coerência clínica? Inversão O sistema consegue gerar: conhecimento → paciente → caso sem depender de uma história previamente escrita? Raciocínio Resultados de investigações conseguem modificar o espaço de hipóteses e o estado do paciente? Esses testes ajudam a distinguir uma base que apenas armazena informação de uma base preparada para alimentar uma simulação clínica generativa. 🏛 Instituto Delyone O Diagnosis integra o ecossistema do Instituto Delyone de Medicina e Tecnologia, dentro de uma abordagem que combina: Medicina · Tecnologia · Pesquisa · Raciocínio Clínico · Linguagem · Engenharia de Sistemas O projeto é desenvolvido de forma modular, rastreável e orientada à reconstrução do conhecimento clínico. 📌 Princípio central > **O caso não é a unidade primária de conhecimento.** >  > **O conhecimento estrutura o espaço clínico.** >  > **O paciente é uma realização possível desse espaço.** >  > **O caso é a apresentação desse paciente.** Status Projeto em desenvolvimento.
